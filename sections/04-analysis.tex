\section{Latency Analysis}
\label{sec:model}
We model one complete Dispatch or Combine operation, from locally available inputs to completion on all participating ranks. Following Swift~\cite{swift}, we distinguish processing time from network traversal time and apply that distinction to the operation's execution order.

\subsection{Operation Latency}
\label{sec:delay-model}
Consider a reference case in which ranks become ready together. Let $L$ be the one-way network propagation and fixed forwarding delay. Let $S$ be the time to transmit the operation's full payload at its bottleneck rate, accounting for concurrent traffic from all ranks. Thus, $S$ describes the collective data pipeline rather than a single flow.

Let $H_{\rm base}$ and $H_{\rm INC}$ denote processing time exposed on the critical path before and during delivery, including endpoint work and, for INC, readiness handling and buffering. Let $C$ denote the subsequent delivery confirmation and local epilogue. Under the same payload rate and the same $C$, the reference schedules are
\begin{align}
 T_{\rm base}&=H_{\rm base}
 +\underbrace{L}_{\text{pre-barrier}}
 +\underbrace{(S+L)}_{\text{data delivery}}+C,
 \label{eq:base}\\
 T_{\rm INC}&=H_{\rm INC}+(S+L)+C.
 \label{eq:inc}
\end{align}
These are operation completion times. The terms describe successive work on the critical path, not sums of independently selected per-rank measurements.

\subsection{How Early Upload Creates Overlap}
\label{sec:readiness-analysis}
In the baseline, a rank receives peer readiness signals before sending data. This exposes a control traversal ahead of the payload. With INC, READY travels toward the network node while data follows it. If all required readiness signals reach the node before the corresponding data must be forwarded, token transmission proceeds without waiting for readiness signals to return to the source. For the reference schedule, the difference is
\begin{equation}
 \Delta T=L+H_{\rm base}-H_{\rm INC}.
 \label{eq:gain}
\end{equation}
With simultaneous readiness and unchanged forwarding throughput, early upload can hide one one-way network traversal, as illustrated in Figure~\ref{fig:timing}(A--B). For symmetric network paths, this is approximately half a network RTT before additional processing overhead. The net benefit includes $H_{\rm base}-H_{\rm INC}$. The reference assumes sufficient staging, no PFC pause, and the same subsequent work $C$ in both designs.

\subsection{Unequal Readiness and Backpressure}
\label{sec:skew}
When ranks become ready at different times, early ranks can fill INC staging while the remaining ranks prepare. Forwarding still waits for the required READY signals. The benefit depends on which data are ready at that point and whether the output link can forward them promptly.

A late rank may dominate the operation's completion time, and accumulated data may queue at an INC output. PFC can further delay upload. In these cases, the comparison must follow the actual data-delivery and operation-finish times; the reference value $L$ is not a fixed saving. Likewise, a pre-barrier measurement includes local work and peer waiting in addition to propagation.

For measurements, the operation completes when the last participating rank finishes. Earlier delivery at one destination contributes to an overall speedup only if it advances that completion time. This connects the readiness-overlap mechanism to the operator and inference metrics in Section~\ref{sec:evidence}.
