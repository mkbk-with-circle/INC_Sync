\section{Latency Analysis}
\label{sec:model}
We model a complete Dispatch or Combine operation as READY, data transfer, and post-barrier. INC starts upload after issuing READY, overlapping data movement with the wait for peer readiness.

\subsection{Three-Stage Model}
\label{sec:delay-model}
Let $T_{\rm ready}$ be the pre-barrier duration, $T_{\rm data}$ the data-transfer phase, and $T_{\rm post}$ the post-barrier and subsequent local epilogue. The data phase includes the sender-side work needed to enter the post-barrier. The baseline executes these stages in sequence:
\begin{equation}
 T_{\rm base}=T_{\rm ready}+T_{\rm data}+T_{\rm post}.
 \label{eq:base}
\end{equation}

Following Swift's separation of processing and network delay~\cite{swift}, consider a reference with simultaneous rank readiness and comparable communication paths:
\begin{equation}
 T_{\rm ready}=T_{\rm issue}+L+T_{\rm observe}.
 \label{eq:ready}
\end{equation}
Here $T_{\rm issue}$ is the local work to prepare and issue READY, $L$ is its one-way network traversal, and $T_{\rm observe}$ is the subsequent signal checking and local synchronization before DATA starts. These terms describe the critical execution path; per-rank minimum measurements are reported separately in Section~\ref{sec:evidence}.

\subsection{Overlapping the Wait for READY}
\label{sec:readiness-analysis}
In the baseline, ranks finish the entire READY stage before sending DATA. With INC, each rank issues READY and starts uploading. READY and DATA travel toward the network node together; INC holds any early data until the required signals have arrived and destination buffers are writable. Using the same reference data-transfer duration and subsequent completion work, the INC schedule is
\begin{equation}
 T_{\rm INC}=T_{\rm issue}+T_{\rm data}+T_{\rm post}+T_{\rm extra}.
 \label{eq:inc}
\end{equation}
The local issue time remains. $T_{\rm extra}$ includes readiness processing still required at INC or the endpoints and additional delay from buffering or waiting to forward. The ordinary source-to-destination traversal of DATA is already included in $T_{\rm data}$.

The reference difference is therefore
\begin{equation}
 \Delta T=L+T_{\rm observe}-T_{\rm extra}.
 \label{eq:gain}
\end{equation}
The network component is one serialized READY traversal, $L$, which is approximately half a network RTT for symmetric paths. The net benefit also depends on how much endpoint observation work is replaced and how much processing and waiting INC adds. Half a network RTT is not half the measured pre-barrier duration.

\subsection{Readiness Skew and Forwarding Delays}
\label{sec:skew}
The reference uses simultaneous readiness, the same payload rate, and the same post-barrier work. Sufficient staging and forwarding capacity allow upload to proceed while READY is collected. If INC must hold data longer or drain a congested output, the additional wait contributes to $T_{\rm extra}$; PFC pauses can have the same effect.

When ranks become ready at different times, early ranks can upload while later ranks prepare. Forwarding still waits for the required READY signals. The full operation finishes with the last participating rank, so the benefit depends on whether early upload advances that completion time. The one-way-traversal reference is interpreted under its stated timing conditions.
